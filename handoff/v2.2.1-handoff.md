## 1. 修了什么

1. **Bug1 冻结/空白**：DXGI 恢复预算跨窗口连丢计数（`DXGI_LOST_STREAK_LIMIT=2`），
   超窗连丢且无成功帧即钉 GDI；成功帧清零；突发 3 次上限保留。
2. **Bug2 二维码白窗**：新增 `src/compat_display.rs`。GDI 回退（含 scrap 创建内/帧中途
   **静默**回退、便携宿主循环）时后台安装/插入自带签名 usbmmidd 虚拟显示：
   clone staging 优先、被拒则 IDD 主显示；已有间接显示活动则 Skip。
3. **钉 GDI**：IDD 下仅 GDI 合成面可读（DXGI duplication 仍盲，实测），compat 生效期间
   采集钉住 GDI（video_service 帧循环 + portable_service 宿主循环薄钩子）。
4. **断连重插**：上游连接关闭 `reset_all()` 会拔监视器；`ensure_async` 每次复查拓扑、
   被拔后重插；Skip 也置 ENABLED（向日葵遗留场景同样钉 GDI）。

钩子共 10 处，全部 `#[cfg(windows)]` 薄钩子；健康机器 DXGI 正常 → 零影响。

## 5. 已知限制

- GPU-P 上 clone 标签不保证物理屏镜像（实际 IDD 唯一主显示）；真实物理屏机器
  clone 通常被 WDDM 支持，未实测。
- 物理屏 + 拒绝 clone + 物理输出不脱离的组合：IDD 主显示为扩展空桌面，未见实例，接受为限制。
- 本机 Oray IDD 节点 pending reboot（向日葵侧 plug 状态丢失），下次自然重启清除。
- 兼容采集期间帧率/编码走 GDI 路径（CPU 拷贝），受影响机器才有此代价；健康机器不变。
